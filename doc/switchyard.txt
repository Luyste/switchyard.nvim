1. INTRODUCTION                                             *switchyard-intro*
                                                                  *switchyard*

switchyard is a Neovim plugin for working with several AI coding agents at
once, each in its own git worktree. It gives you one small screen to switch
between worktrees and agents, a terminal split to talk to an agent, a prompt
builder that sends code from your editor, and an editor that keeps up with
what the agent is doing.

Concepts:                                                *switchyard-concepts*

Tracks ~
    Git worktrees, one checkout of the repository per task, made and
    removed with `git worktree`.

Trains ~
    Agent sessions: pi, Claude Code, codex or any other CLI agent. Each one
    runs in its own tmux session, so switchyard can find it, show it in a
    split and type prompts into it, and it keeps running when Neovim closes.

The yard ~
    One floating window in Neovim to switch worktrees and manage agents.
    See |switchyard-yard|.

The link ~
    The editor is linked to one agent. Prompts go to that agent, and when
    it moves to another worktree, the editor follows. See
    |switchyard-linking|.

==============================================================================
2. REQUIREMENTS                                      *switchyard-requirements*

- Neovim 0.12 or later.
- git.
- tmux. Agents run in tmux sessions; switchyard finds them there.
- An agent CLI: pi (https://pi.dev), Claude Code or codex work out of the
  box, any other one can be added (|switchyard-config-agents|). No agent
  extensions are needed.

- fzf-lua (https://github.com/ibhagwan/fzf-lua) and fzf: the yard is an
  fzf-lua picker.
- fd: finds the projects (`%` in the yard).

Run `:checkhealth switchyard` to see what is found (|switchyard-health|).

3. SETUP                                                    *switchyard-setup*

With the built-in plugin manager (|vim.pack|): >lua
    vim.pack.add({ "https://github.com/Luyste/switchyard.nvim" })
    require("switchyard").setup({})
<
With lazy.nvim: >lua
    {
      "Luyste/switchyard.nvim",
      config = function()
        require("switchyard").setup({})
      end,
    }
<
|switchyard.setup()| is required: it starts watching agent sessions and,
with |switchyard-config-live_reload|, reloading files.

4. KEYMAPS                                                *switchyard-keymaps*

switchyard sets no global keymaps. It gives you functions to map (see
|switchyard-api|). Keys inside switchyard's own windows are buffer-local;
the yard's keys can be changed with |switchyard-config-keys|.

A starting point: >lua
    local function sy(name)
      return function()
        require("switchyard")[name]()
      end
    end
    local map = vim.keymap.set

    map({ "n", "t" }, "<leader>yy", sy("open_yard"),
      { desc = "switchyard: the yard" })
    map({ "n", "t" }, "<leader>yv", sy("toggle_view"),
      { desc = "switchyard: show/hide the agent" })
    map({ "n", "t" }, "<leader>yj", sy("focus_view"),
      { desc = "switchyard: jump between agent and editor" })
    map({ "n", "x" }, "<leader>yp", sy("prompt"),
      { desc = "switchyard: prompt (+ selection)" })
    map("n", "<leader>yl", sy("prompt_line"),
      { desc = "switchyard: prompt with this line + diagnostics" })
    map({ "n", "x" }, "<leader>yd", sy("dispatch"),
      { desc = "switchyard: dispatch a task" })
    map({ "n", "t" }, "<leader>yh", sy("link_here"),
      { desc = "switchyard: link an agent in this worktree" })
    map("n", "<leader>yo", sy("open_external"),
      { desc = "switchyard: agent in an external terminal" })
<
<leader> does not work in terminal mode (you would type it to the agent), so
for the "t" mappings pick keys that do not reach the agent. In Neovide the
Cmd key works well: <D-y>, <D-j>, <D-J> and so on.

The function form (`sy("open_yard")`) keeps your config from breaking if a
name ever changes.

5. THE YARD                                                  *switchyard-yard*

Open it with |switchyard.open_yard()| or |:Switchyard|: one fzf-lua picker
with three views. Type a prefix first to choose one; without a prefix you
get |switchyard-config-yard.view|. `%sho` searches the projects for "sho".

Views ~
                                                   *switchyard-yard-worktrees*
& worktrees      Every worktree of the repository. `@` marks the current
                 one, `● <name>` (green) the worktree of the linked agent
                 (the one your prompts go to), `● n` the number of agents
                 in a worktree. Outside a repository: the folder itself.
                 Preview: `git status` and recent commits.
                                                      *switchyard-yard-agents*
* agents         Every agent of the repository, with its worktree. `●`
                 marks the linked agent. Preview: the agent's screen.
                                                    *switchyard-yard-projects*
% projects       The current project, pinned folders, projects with agents
                 (`● n`), recent ones, then every git repository `fd` finds
                 under the roots (|switchyard-config-projects|). The last
                 scan is cached, so the list shows at once.

Keys ~
                                                        *switchyard-yard-keys*
The names in brackets are the entries of |switchyard-config-keys|. Plain
letters type into the search, so actions use Alt (macOS: Option as Meta).
Keys act on the kind of row under the cursor.

Key         Worktree                      Agent ~
<CR>        switch the editor there       go to: switch to its worktree
 (activate)                               and link it
<M-CR>      peek: switch, keep the link   link it, stay where you are
 (alt_activate) and the viewer            (the picker stays open)
<M-n> (new) new worktree                  new agent in a worktree
<M-d>       dispatch a task               dispatch a task
 (dispatch)
<C-x>       remove the worktree (choose   stop the agent
 (remove)   to keep or stop its agents)
<M-f> (fork) fork the linked agent into   fork this agent into another
            this worktree                 (or a new) worktree
<M-a>       start a new agent here
 (start_agent)
<M-c>       continue an earlier session
 (continue_agent) here (a list, newest first;
            running ones left out)
<M-y>       copy the path
 (copy_path)
<M-v> (view)                              show it in the viewer split
<M-g>                                     open it in an external terminal
 (external)
<M-s> (send)                              write a prompt for this agent
<M-r> (rename)                            rename its tmux session
<C-r>       refresh                       same
 (refresh)
<F1>        every key                     same

On a project: <CR> switches to it (its main worktree), <M-CR> peeks, <M-a>
starts an agent there (the editor stays), <M-y> copies the path.

Actions that remove or stop something ask for confirmation (the picker
closes for the question and comes back after). With several agents
installed, starting an agent asks which one.

6. LINKING, FOLLOWING AND PEEKING                         *switchyard-linking*

Your editor is linked to one agent. The link decides where prompts go and
which agent the editor follows.

Arrival rules ~
                                                    *switchyard-arrival-rules*
When the editor arrives in a folder (the global current directory
changes): the editor goes with the agent of where it is.

- an agent there: the editor links to it and shows it in the viewer. With
  several, the one you used last (linked or viewed), else the most recently
  started;
- no agent: the editor unlinks and the viewer closes.

At startup only the link is set; the viewer stays closed.

Following ~
                                                        *switchyard-following*
When the linked agent moves to another worktree, the editor switches there
(see |switchyard-config-follow|). Only an actual move counts: after keeping
the link in another worktree, the editor is not pulled back. Switching the
editor yourself never moves an agent.

Switching closes the old worktree's file buffers and stops language
servers. It refuses when a buffer has unsaved changes.

Peeking ~
                                                             *switchyard-peek*
Peek (<M-CR> on a worktree or project, also a folder outside git) switches
the editor without touching the link or the viewer: look around in worktree
B, copy a snippet, and send it to your agent in A. Changed your mind? |switchyard.link_here()| links an agent of the
worktree you are in.

==============================================================================
7. THE VIEWER                                              *switchyard-viewer*

|switchyard.toggle_view()| shows the linked agent's terminal in a split on
the right, and hides it again. Without a linked agent it shows an agent of
the current worktree (and asks which one when there are several). The
split's width is set by
|switchyard-config-viewer.width|.

|switchyard.focus_view()| jumps between the agent and your code, in terminal
and normal mode. It opens the viewer when it is hidden.

The bar on top of the viewer shows the agents you can see here, with `●` on
the linked one. A NORMAL badge warns you when your keys do not reach the
agent; press `i` to type again.

The viewer is for typing to the agent. Choosing which agent to see happens
in the yard (`v` in the agents view). Viewing an agent does not link it.

|switchyard.open_external()| opens the linked agent in a new terminal window
instead: Ghostty, kitty, WezTerm, Alacritty or Terminal.app, or your own
command (see |switchyard-config-terminal|).

8. THE PROMPT BUILDER                                      *switchyard-prompt*

|switchyard.prompt()| opens a small input for a prompt to the linked agent.
In visual mode, the selection is added as context first. The title shows the
target agent.

The draft is kept when the builder closes (it also closes as soon as you
click elsewhere), so you can collect several pieces of code before sending.

|switchyard.prompt_line()| adds the current line with its diagnostics.

Keys ~
                                                      *switchyard-prompt-keys*
    <CR>             send (insert and normal mode)
    <S-CR>, <C-j>    new line (insert mode)
    <C-f>            add the file you came from, as a path
    <C-d>            remove a context
    <C-t>            choose the target: another agent of this repository,
                     or a dispatch (|switchyard-dispatch|); the link stays
    <C-o>            hand over: paste into the agent's own input without
                     sending, and show it in the viewer
    q, <Esc>         close, keeping the draft (normal mode)
    <C-x>            clear the draft (normal mode)

What the agent receives ~
Your text, followed by each piece of context as a fenced code block with its
path and line numbers. Paths are relative to the agent's worktree when the
file is in it, and absolute otherwise, so an agent in another worktree never
edits the wrong checkout.

After sending, the draft is cleared and the next prompt goes to the linked
agent again.

==============================================================================
9. DISPATCH                                              *switchyard-dispatch*

|switchyard.dispatch()| (or `N` in the yard) opens the prompt builder aimed
at a new worktree. Write the task and press <CR>: switchyard suggests a
branch name from the first line, creates the worktree, and starts an agent
there with your text as its first message. Your editor and your link stay
where they are; the new agent shows up in the yard.

In visual mode, the selection comes along as context.

==============================================================================
10. LIVE RELOAD                                             *switchyard-live*

Live reload ~
                                                      *switchyard-live-reload*
With |switchyard-config-live_reload| on (the default), files open in Neovim
reload when an agent changes them, also while you are typing in the viewer.
Buffers with unsaved changes are never touched.

==============================================================================
11. STATUSLINE                                         *switchyard-statusline*

Two functions for your statusline. They only read cached values (no file
access), so they are cheap to call on every redraw: >lua
    -- "pi-shoebox" or "pi-shoebox (in other-worktree)"
    require("switchyard").status()
    -- "DRAFT" or "DRAFT 2" while a prompt draft waits
    require("switchyard").draft_status()
<
The yard is an fzf-lua window ('filetype' "fzf"). switchyard's menus and
the prompt builder have 'filetype' "switchyard", so a statusline can
recognise them.

12. FUNCTIONS                                                 *switchyard-api*

All functions live in the `switchyard` module: >lua
    require("switchyard").open_yard()
<
                                                          *switchyard.setup()*
setup({opts})
    Set the options (see |switchyard-config|), start tracking agent
    sessions, and start live reload when enabled.

                                                      *switchyard.open_yard()*
open_yard()
    Open the yard (|switchyard-yard|), or focus it when it is open.

                                                         *switchyard.switch()*
switch({dir})
    Switch the editor to the folder {dir}: close the old folder's files,
    stop language servers, change the directory and fire
    |SwitchyardSwitched|. Refuses when a buffer has unsaved changes.

                                                      *switchyard.link_here()*
link_here()
    Link an agent of the editor's current worktree (the one viewed last,
    else the most recently started). Useful after a peek.

                                                    *switchyard.toggle_view()*
toggle_view()
    Show or hide the viewer (|switchyard-viewer|).

                                                     *switchyard.focus_view()*
focus_view()
    Jump between the viewer and the editor. Opens the viewer when hidden.

                                                  *switchyard.open_external()*
open_external()
    Open the linked agent in an external terminal window
    (|switchyard-config-terminal|).

                                                         *switchyard.prompt()*
prompt()
    Open the prompt builder (|switchyard-prompt|). In visual mode, add the
    selection as context first.

                                                    *switchyard.prompt_line()*
prompt_line()
    Add the current line and its diagnostics as context, and open the
    prompt builder.

                                                       *switchyard.dispatch()*
dispatch()
    Open the prompt builder for a dispatch (|switchyard-dispatch|). In
    visual mode, add the selection as context first.

                                                         *switchyard.status()*
status()
    For statuslines: the linked agent's tmux session name, with
    " (in <worktree>)" when it works in another worktree.
    Empty string when not linked.

                                                   *switchyard.draft_status()*
draft_status()
    For statuslines: "DRAFT" while a prompt draft waits, "DRAFT n" with n
    pieces of context. Empty while the builder is open or the draft is
    empty.

13. CONFIGURATION                                          *switchyard-config*

Pass options to |switchyard.setup()|. The defaults: >lua
    require("switchyard").setup({
      agents = { "pi", "claude", "codex" },
      follow = true,
      terminal = "auto",
      live_reload = true,
      yard = {
        view = "worktrees",
        prefixes = { worktrees = "&", agents = "*", projects = "%" },
      },
      projects = {
        roots = { "~" },
        exclude = { "Library", "node_modules", ".cache", ".Trash",
          ".local/share/nvim", ".oh-my-zsh", ".claude/plugins" },
        pinned = {},
      },
      viewer = {
        width = 0.45,
      },
      keys = {
        yard = {
          activate = "enter", alt_activate = "alt-enter",
          refresh = "ctrl-r", new = "alt-n",
          remove = "ctrl-x", fork = "alt-f", dispatch = "alt-d",
          start_agent = "alt-a", continue_agent = "alt-c",
          copy_path = "alt-y", view = "alt-v", external = "alt-g",
          rename = "alt-r", send = "alt-s",
        },
      },
    })
<
Tables are merged with the defaults; lists (`agents`) are replaced.

                                                    *switchyard-config-agents*
agents ~
    Default: `{ "pi", "claude", "codex" }`
    The agents switchyard knows, by preset name or as your own table. Only
    installed ones (their program is found) are used.

    switchyard finds agents in tmux: every pane in which a configured agent
    runs (as a program, or as a script run by node, bun, deno, python or
    ruby) is an agent session. Prompts are typed into its pane (bracketed
    paste, then Enter). An agent table: >lua
    {
      name = "aider",          -- in the yard and tmux session names
      cmd = { "aider" },       -- start a new session
      continue = { "aider", "--restore-chat-history" }, -- optional
      history = nil,           -- optional: function(cwd, running)
                               -- returning earlier sessions, newest
                               -- first: { { time, title, cmd } }
      task = true,             -- optional: a task goes after `cmd`, or
                               -- a function(task) returning the command
      fork = nil,              -- optional: function(session, note)
                               -- returning a command copying the session
      match = "python.*aider", -- optional: Lua pattern for its process
    }
<
    Good to know: a prompt sent while an agent shows a question (a
    permission prompt, "do you trust this folder?") presses Enter on that
    question, and text half-typed in the agent's input is sent along.

                                                    *switchyard-config-follow*
follow ~
    Default: `true`
    Follow the linked agent when it moves to another worktree
    (|switchyard-following|).

                                                  *switchyard-config-terminal*
terminal ~
    Default: `"auto"`
    The external terminal for |switchyard.open_external()| and `g` in the
    yard. One of "auto" (the first one found of ghostty, kitty, wezterm,
    alacritty, terminal.app), "ghostty", "kitty", "wezterm", "alacritty",
    "terminal.app", or a function that receives the command to run (a
    list) and returns the full command (a list) that opens a terminal
    window running it: >lua
        terminal = function(cmd)
          return vim.list_extend({ "foot", "-e" }, cmd)
        end,
<
                                               *switchyard-config-live_reload*
live_reload ~
    Default: `true`
    Reload open files when agents change them (|switchyard-live-reload|).

                                                 *switchyard-config-yard.view*
yard.view ~
    Default: `"worktrees"`
    The view without a prefix: "worktrees", "agents" or "projects".

                                             *switchyard-config-yard.prefixes*
yard.prefixes ~
    Default: `{ worktrees = "&", agents = "*", projects = "%" }`
    Typed first in the yard's search, a prefix shows that view. Avoid fzf's
    own search characters (^ $ ' ! |).

                                                  *switchyard-config-projects*
projects ~
    The projects view (`%`). Lists are replaced, not merged.
      roots     where `fd` looks for git repositories. Default: `{ "~" }`
      exclude   folder names or paths `fd` skips (passed as --exclude)
      pinned    folders always listed, git or not, e.g. a config folder
                kept in a bare dotfiles repository: >lua
                  pinned = { "~/.config/nvim" }
<

                                              *switchyard-config-viewer.width*
viewer.width ~
    Default: `0.45`
    Share of the editor's width for the viewer split.

                                                      *switchyard-config-keys*
keys.yard ~
    Keys inside the yard, as fzf key names. See |switchyard-yard-keys| for
    what each one does in each view.

    Name            Default     Worktrees view / agents view ~
    activate        enter       switch / go to (switch and link)
    alt_activate    alt-enter   peek / link only
    refresh         ctrl-r      refresh
    new             alt-n       new worktree / new agent in a worktree
    remove          ctrl-x      remove worktree / stop agent
    fork            alt-f       fork the linked agent here / fork this one
    dispatch        alt-d       dispatch a task
    start_agent     alt-a       start an agent here (worktrees)
    continue_agent  alt-c       continue an earlier session here (worktrees)
    copy_path       alt-y       copy the path (worktrees)
    view            alt-v       show in the viewer (agents)
    external        alt-g       open in an external terminal (agents)
    rename          alt-r       rename the tmux session (agents)
    send            alt-s       write a prompt for it (agents)

15. EVENTS                                                 *switchyard-events*

switchyard fires |User| autocommands.

                                                          *SwitchyardSwitched*
SwitchyardSwitched
    After the editor switched worktrees. The event data is
    `{ from = <old folder>, to = <new folder> }`. For example, to reopen a
    file tree: >lua
        vim.api.nvim_create_autocmd("User", {
          pattern = "SwitchyardSwitched",
          callback = function(args)
            require("nvim-tree.api").tree.open()
            vim.cmd.wincmd("p")
          end,
        })
<
                                                   *SwitchyardSessionsChanged*
SwitchyardSessionsChanged
    When agents start, stop or move, or an agent's tmux name becomes known
    or changes.

                                                       *SwitchyardLinkChanged*
SwitchyardLinkChanged
    When the link changes (another agent, or no agent).

==============================================================================
16. HEALTH CHECK                                           *switchyard-health*

Run: >vim
    :checkhealth switchyard
<
It reports:
- programs: git and tmux, with their versions;
- options: the external terminal that will be used, and whether follow
  edits is available on this system;
- agents: for each entry in |switchyard-config-agents|, whether its program
  is installed, and how many of its sessions run in tmux.
